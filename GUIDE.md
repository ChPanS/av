# av · livecoding — справочник по визуальным uniforms

Как музыка из Strudel превращается в «ручки» (uniforms) для шейдера. Логика — в `bridge.js`,
объявление/прокидка в шейдер — авто-генерируются в `renderer.js` из объекта `uniforms`.

---

## 1. Поток данных

```
Strudel scheduler → вывод (audio.js) → handleHap (bridge.js) → объект uniforms
                                          ↑
                          syncTags(код паттерна) — сканирует .vis("...") в тексте
                          ДО компиляции шейдера и решает, какие юниформы вообще есть

renderer.js: каждый кадр гасит огибающие (decay, по реальному dt) и прокидывает
             uniforms в шейдер
GLSL: твоя функция mainImage(out vec4 fragColor, in vec2 fragCoord)
```

**Никакого угадывания по имени сэмпла нет.** Единственный способ завести канал —
явный тег `.vis("...")` на конкретной дорожке. Нет тега — нет юниформа — шейдер,
который на него ссылается, не скомпилируется (это осознанно: паттерн и шейдер
должны буквально совпадать по тегам, никакой скрытой магии между ними).

---

## 2. Синтаксис тега: префикс + Имя

```
.vis("<префикс><Имя>")
```

- **префикс** — строчными буквами, определяет ТИП канала (что трекать и как это гаснет).
  В имя юниформа он НЕ попадает — только управляет тем, что генерируется.
- **Имя** — с большой буквы, придумывает пользователь как угодно (`Kick`, `Huy`, `MyWeirdSynth`…).
- Имя юниформа в шейдере = `u` + Имя (без буквы префикса). Что придумал в `.vis()`
  после префикса, то и увидишь после `u` в шейдере.

Три префикса из коробки:

| Префикс | Смысл | Что трекает | Юниформ для `.vis("xName")` |
|---|---|---|---|
| `d` | удар (drums/hits) | только громкость, импульс + быстрое затухание | `uniform float uName;` |
| `i` | инструмент | велосити (гаснет) + питч (держится) | `uniform AVInstrument uName;` → поля `.vel` и `.pitch` |
| `p` | только питч | держит последнюю ноту, громкость не участвует | `uniform float uName;` (хранит класс ноты) |

Примеры (буквой префикса управляется ТИП, дальнейшее имя — буквально):

```js
.vis("dKick")   → uKick                        // импульс громкости, гаснет быстро
.vis("dSnare")  → uSnare
.vis("dHat")    → uHat
.vis("iLead")   → uLead.vel, uLead.pitch        // структура: велосити гаснет плавно, питч держится
.vis("iBass")   → uBass.vel, uBass.pitch
.vis("pArp")    → uArp                          // держит класс ноты 0..1, не гаснет
```

`i`-каналы — это ОДИН uniform-структуры (WebGL2 struct uniform), а не два разных
имени: в шейдере пишешь `uLead.vel` и `uLead.pitch` через точку, как у обычного
GLSL-объекта. Структура объявляется автоматически (`struct AVInstrument { float
vel; float pitch; };`) один раз в начале шейдера, если хотя бы один `i`-тег есть в
паттерне.

**Редактор шейдера подсказывает.** Начни печатать `uLe` — автокомплит покажет
`uLead` из текущего каталога (он сканит `.vis()` из редактора паттерна вживую, ещё
до Play). Допечатай точку — `uLead.` — подсветит `vel` и `pitch`. Для `d`/`p`-тегов
(просто `float`) подсказка покажет только имя без точки.

Тег вешается на КОНКРЕТНУЮ дорожку (не на весь `stack`):

```js
stack(
  s("bd*4").vis("dKick"),
  s("~ cp ~ cp").vis("dClap"),
  note("<c2 g1>").s("sawtooth").vis("iBass"),
  note("c5 e5").s("triangle").vis("pArp"),
)
```

Один и тот же тег можно вешать на несколько разных дорожек (например, `dKick` и на
основной брейк, и на DnB-вставку) — они будут светить в один и тот же uniform.

**Коллизия имён:** если два РАЗНЫХ тега сводятся к одному Имени (например `dPad` и
`iPad` — оба дают `uPad`, просто разных типов), второй по счёту в тексте паттерна
пропускается с предупреждением в дебаг-лог, юниформ не дублируется. Выбирай разные
Имена для разных тегов.

## 3. Значения каналов

- **`uName` (d, float)** — при хите: `max(текущее, 0.2 + gain)`, потолок 1.5. Гаснет
  экспоненциально между хитами.
- **`uName.vel` (i, float)** — то же самое, потолок 1.0.
- **`uName.pitch` / `uName` (p, float)** — класс ноты в октаве, 0..1 (без учёта
  октавы), обновляется только если у события есть нота; **никогда не гаснет**,
  держит последнее значение.

## 4. Скорость затухания — из самого Strudel, не из таблицы имён

Раньше скорость гашения жёстко прописывалась per-инструмент по имени
(`uPadVel: 0.94`, `uArpVel: 0.88`, …) — это и было угадыванием, которое просили убрать.

Теперь: если у события паттерна задан ADSR-контрол Strudel — `.release(sec)` или
`.decay(sec)` — **это реальное время звучания ноты**, и оно используется как есть
для визуального затухания. Ничего не задано — берётся дефолт по ТИПУ канала
(удар гаснет быстро ~0.12с, инструмент — плавно ~0.35с). Питч-каналы не гаснут вообще.

```js
note("c3").s("gm_fx_atmosphere:1").release(1.2).vis("iPad")
// uPad.vel будет гаснуть за ~1.2с — ровно как гаснет сам звук атмосферы,
// а не по случайной константе из таблицы для "pad"
```

Затухание считается по реальному времени кадра (`dt`), не по предположению «60 кадров
в секунду» — на слабом устройстве или при просадке FPS скорость угасания визуально
не меняется.

## 5. Глобальные uniforms (без тегов, считаются из КАЖДОГО события)

| Uniform | Диапазон | Смысл |
|---|---|---|
| `uResolution` | px (vec2) | размер кадра |
| `uTime` | растёт | секунды с запуска |
| `uPitch` | 0..1 | высота последней ноты вообще (класс в октаве), из любого события с нотой |
| `uHue` | 0..1 | оттенок, плавно ведётся за `uPitch` (dt-based lerp) |
| `uEnergy` | 0..1 | плотность/громкость всего потока (прокси интро↔дроп), из `gain` каждого события |
| `uBeat` | 0..N | позиция в лупе в циклах; `floor` = номер такта |
| `uLoop` | 0..1 | позиция в лупе нормированная |
| `uBeatFrac` | 0..1 | фаза внутри текущего цикла |

Это не угадывание по имени — они одинаково считаются из любого хита/ноты независимо
от того, есть на нём тег или нет, так что не конфликтуют с идеей «явные теги для
конкретных инструментов».

Длина лупа для `uBeat` берётся из комментария `// loop: N` в начале паттерна (иначе 24).

## 6. Как добавить новый ТИП префикса (не просто новый инструмент — новый способ трекать)

Всё в одном месте, `bridge.js` → `KIND_SPECS`:

```js
const KIND_SPECS = {
  d: { defaultTau: 0.12, cap: 1.5, channels: (base) => ({ [base]: 'level' }) },
  i: { defaultTau: 0.35, cap: 1.0, channels: (base) => ({ [base+'.vel']:'level', [base+'.pitch']:'pitch' }) },
  p: { defaultTau: null, cap: 1.0, channels: (base) => ({ [base]: 'pitch' }) },
};
```

`base` — это уже готовое `"u" + Имя`. Добавь свой ключ (например `x`) с нужными
`channels()` (какие поля и какого вида — `'level'` гаснет, `'pitch'` держится;
несколько полей = сгенерируется struct с этими полями), дефолтным `tau` и потолком
`cap`. Новый префикс сразу заработает в тегах `.vis("xИмя")` — ни `renderer.js`, ни
автокомплит трогать не нужно, они читают всё из `bridge.js` (`shaderUniformDecls()` /
`scanUniformCatalog()`).

Обычный новый инструмент/удар НЕ требует правок кода вообще — просто напиши новый тег
в паттерне (`.vis("dHuy")`) и используй `uHuy` в шейдере.

## 7. Подводные камни

- **Тег на дорожку, не на `stack`.**
- **Тег — это буквально строковый литерал** в `.vis("...")` — юниформы собираются
  regex-сканом текста паттерна ДО его выполнения. `.vis(myVar)` с переменной
  распознан не будет — юниформ не появится, шейдер, ссылающийся на него, не
  скомпилируется. Если видишь ошибку компиляции про неизвестный uniform — проверь,
  что тег написан прямо строкой в том паттерне, который сейчас в редакторе.
- **Опечатка/неизвестный префикс** (например `.vis("kick")` без заглавной буквы после
  префикса, или `.vis("zKick")` с не заведённым префиксом `z`) — не роняет паттерн,
  но пишет предупреждение в дебаг-лог (кнопка debug) и юниформ не создаёт. То же для
  коллизии имён (см. раздел 2).
- **Юниформ появляется только после Play** — правишь теги в паттерне, юниформы
  синхронизируются заново перед каждой компиляцией шейдера (и на старте). Автокомплит
  в редакторе шейдера при этом видит новые теги СРАЗУ, без Play — он сканит live-текст
  паттерна отдельно и ничего не компилирует.
- **`uName.pitch` / `uName` (p) — класс в октаве (0..1)**, без различения октав;
  для «высоты вообще» складывай с громкостью/энергией в шейдере.
- **Аккорд = несколько событий разом** → level-каналы получают суммарный вклад
  (через `max`), tau берётся с последнего события аккорда.
- **`uName` (d) до ~1.5** — не нормирован в 0..1, учитывай в шейдере.
- **Имя структуры `AVInstrument`** зарезервировано под `i`-каналы — не переопределяй
  свой struct с таким же именем в пользовательском коде шейдера.
- **Подсветка нот в редакторе** опирается на позиции из транспайлера; работает для
  кода паттерна (не шейдера).
